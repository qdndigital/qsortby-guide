Every term the app uses, in the app's own words. If a word here disagrees with a screen, the screen is wrong and we want to know.

| Term | Meaning |
| --- | --- |
| **Surface** | Any place on your storefront whose order QSortby decides — a collection page, or a theme block. |
| **Recipe** | A ranking formula with a name. It decides order only — never prices, products or collection membership. Six are offered; eleven **criteria** sit behind them. |
| **Criteria** | The eleven things a collection can be ranked by — best selling, top revenue, most profitable, customer favorites, trending, selling fast, newest, top rated, engagement, personalize, your own formula. |
| **Window** | The period a recipe counts. Rolling (the last N days or hours), period (a fixed calendar span) or snapshot (frozen at a moment). Five criteria ignore it, and the app says which. |
| **Velocity** | Units sold in the chosen window. This is what "best seller" means here. |
| **Trend** | Rate of change in sales, not the total. |
| **Sales floor** | What stops a jump from one unit to three winning Trending now or Profit first: a product well below the best seller's sales keeps its rank but has its score damped. |
| **Snapshot** | The exact order produced by one sort, kept so it can be restored or explained. The first one is the order before QSortby. |
| **Test mode** | A state in which a collection keeps computing its order on schedule and publishes nothing to the real collection. |
| **Preview collection** | The temporary `QSortby - … - Test` collection test mode can publish, so you see the tested order in your own theme. It deletes itself. |
| **Slot** | A position on a surface that personalization is allowed to rewrite. |
| **Rule** (personalization) | Groups of shoppers, each with its own order of priorities. Exactly one is published at a time. |
| **Group** | A set of shoppers selected by AND-ed conditions. Anyone matching no group falls through to *Everyone else*. |
| **Audience** | A group of shoppers computed from your store's own behaviour. |
| **Signal** | One of the twelve things a group's priorities can weigh — recently viewed, top sellers, bought together, intent match and so on. |
| **Why this order** | The real ranker's order for one group, with the per-signal arithmetic that produced it. |
| **Goes with** | A rule that keeps related products adjacent after ranking. Written once and used by as many collections as you like; a collection can apply several, and one can be switched off on a collection without changing the rule anywhere else. |
| **Set** | Products a Goes-with rule has grouped, which travel together in a sorted collection. |
| **Anchor · partner** | In a *Bring company to a product* rule, the anchor keeps its position and partners move to it. |
| **Padded** | A suggestion slot filled by a best seller because there was not enough co-purchase data to pair honestly. Always labelled, and never counted back as evidence that the pair was real. |
| **Touch point** | One of the six places an upsell offer can appear: cart drawer, free-shipping bar, Frequently bought together, thank-you page, popup, in-checkout. |
| **Offer** | One configured upsell at one touch point. A touch point can hold several, up to what your plan includes. |
| **Display rule** | An IF / AND / THEN condition that narrows who sees an offer. It never widens: an offer with no rule is seen by everyone. |
| **Anchor** (upsell) | A CSS selector and position telling an offer or bar where to attach on a theme QSortby does not know. |
| **Influenced revenue** | Orders containing a product QSortby served in that session. Last-touch, thirty-minute window. Influence, not proven cause. |
| **Directional** | What an experiment's verdict is called, even at 95%. Never "proven". |
| **Arm** | One side of an experiment. A visitor always stays in the same arm. |
| **Intent** | The one thing the app infers about a shopper: what they came for — treating themselves, replacing something, buying a gift, browsing, close to buying. Read from how the visit behaves. |
| **Intent AI** | The layer that reads intent and, where applied, nudges orders and offers toward products tagged for it. Shadow on Pro (reads, reports), applied on Growth. |
| **Reverse trial** | The 10 days after install on which every store runs on the Growth feature set, before settling onto Free. Separate from the 7-day trial on the first paid plan. |
| **Theme app embed** | The switch in your theme editor that lets QSortby see your storefront and render its blocks and offers. Everything behaviour-based depends on it. |
| **Reading your store** | The order and product import that runs by itself after install, and the Tracking card that reports how far it has reached. |
